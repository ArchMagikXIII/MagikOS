# AI

Magikos treats AI coding agents as first-class citizens, but it doesn't pick a favorite for you. Instead, both supported coding-agent CLIs come pre-wired as lazy-loaded launchers. The launchers are tiny [mise](https://mise.jdx.dev/)-managed stubs in `~/.local/bin/`, so nothing is downloaded until the first time you actually run one. Invoke either of these and authenticate when prompted:

| Command    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |

To wrap an additional CLI the same way, run `magikos-mise-install <package> [command-name]`. The stubs are kept current along with everything else mise manages when you run `magikos update` (or the `mup` alias).

### The default agent

Pick your default agent with `magikos default agent <name>` or under _Setup > Defaults > Agent_ in the Magikos Menu (`Super + Space`). If the agent isn't installed yet, picking it installs it first. A fresh Magikos will invite you to make this choice with a one-time notification.

Once you've chosen, `Super + Shift + Ctrl + A` launches the default agent in a dedicated terminal window (or brings up the picker if you haven't chosen yet). You can also launch it straight into a task with `magikos agent prompt "Review this project"`. Agents launched this way run unattended in their respective don't-stop-to-ask modes, so be ready for them to actually do things! And since agents refuse to remember trust for your home directory, launches from `$HOME` start in `~/Work` instead.

There are terminal shortcuts too: `a` runs the default agent inline in the current terminal, while `c` starts OpenCode directly (again in its auto-approving mode).

### Crash diagnosis

Magikos watches systemd-coredump for process crashes. When something segfaults, you'll get a "Process crashed" notification — click it, and the crash is handed to your default agent along with Magikos's diagnose-crash skill, which walks the agent through establishing the facts from the core dump and deciding whether the crash is worth reporting upstream. You can also run it by hand against any PID from `coredumpctl list` with `magikos agent crash <pid>`.

The watching is on by default. Turn it off under _Trigger > Toggle > Crash Capture_ (or with `magikos toggle crash-capture`) and the notifications stop; `magikos agent crash <pid>` still works by hand.

### The Magikos Skill

Agent skills help AI use specific tools in a specific way, and Magikos ships with a default skill for tailoring the system. Like tweaking your Hyprland config, adjusting the bar, or even creating a new theme from scratch. It's symlinked into the generic `~/.agents/skills` location and Antigravity's `~/.gemini/config/skills`, so both supported harnesses pick it up automatically.

But you should treat this skill as experimental. Different models will use it to different effect. It's best to run in plan mode first, so you have an idea of what the agent would like to change. And then be ready to rollback changes or even invoking `magikos reinstall configs`, if the agent makes a mess of everything.
